## 1. 问题现象

| 现象 | 常见触发点 |
|---|---|
| 缺少 preflight、点击快捷方式失败 | 只解压原包，没有恢复外部启动预检 |
| 连不到服务器／进错存档 | 6969 与 6979 混用，或 Launcher 路径仍指向原机器 |
| 缺少 .NET | 新机器未安装所需两种 .NET 10 运行库 |
| 没有小地图 | 启动了原环境，或小地图被小键盘 0 关闭 |
| 进图或 SCAV 结算仍异常 | 不是所有地图、角色、结算组合都已验收 |

## 2. 可能原因

优先核对环境、端口、路径和依赖。对真实运行错误保存同一时段的客户端与服务端日志，再定位具体异常，不使用另一张地图的成功代替失败地图验证。

历史旧账号 PMC 立交桥问题未确认完全修复；该旧账号不在此次主存档列表中。SCAV 结算修复没有补回此前已丢失的库存。正版 Live 的 201 授权错误与此备份的离线启动分开处理。

## 3. 最小验证

1. 校验 44 个分卷及完整逻辑原包 SHA256，排除下载不完整。
2. 核对 [使用方法](使用方法.md) 的预检依赖和 Launcher GamePath。
3. 查看正确环境 `SPT_Runtime/user/logs` 与 `BepInEx` 下的运行日志，核对实际加载插件。
4. 核对账号与地图模式；游戏内验收由使用者决定，本次上传没有进入对局。

## 4. 修复方案

缺失依赖或路径错误时按使用方法恢复对应文件和路径，不改动游戏核心程序集。端口被占用时先识别占用程序并正常退出，不任意强杀。

```powershell
dotnet --list-runtimes
python --version
Get-NetTCPConnection -State Listen -LocalPort 6969,6979 -ErrorAction SilentlyContinue
```

缺少下载分卷时只重新下载缺失或哈希不符的卷，再完整校验；不要跳过校验强行解压。

## 5. 风险与副作用

替换旧存档会回退进度；关闭兼容修复插件可能恢复原故障；不同 EFT/SPT 版本不能直接混用 DLL。原包含测试角色和回归副本，不能将其默认视为日常主账号。

## 6. 成功判据

预检通过、正确服务器可连接、账号正确、插件实际加载。对具体对局问题还需实际出生并正常撤离；SCAV 结算页应与撤离携带物品一致，出售不能报空响应或重复发款。

## 7. 回滚

编辑配置前保存副本；失败时在游戏和服务器退出后恢复该文件。停用插件只移动独立插件目录，并保留其原位置记录；回退时移回。还原存档前另外备份当前版本，绝不通过覆盖整个环境来恢复单一账号。
